Changesビューは「現在、Gitインデックスとワークツリーの間に何があるか」に答えます。

`chronogit`、`chronogit --view changes`、または`1`キーで開きます。

## 表示される変更

左ペインにはGitが報告した未ステージの項目が並びます。

| ワークツリーの状態 | ChronoGitの動作 |
| --- | --- |
| 変更、削除、名前変更、コピー、種類変更 | 追跡済みファイルの未ステージ部分を表示 |
| 未追跡 | `/dev/null`とワークツリーのファイルを比較 |
| 競合 | ワークツリー側の競合状態と取得できる差分を表示 |
| ステージ済みのみ | 意図的に非表示 |
| ステージ済みと未ステージの両方 | インデックスからワークツリーへの変更だけを表示 |

ChronoGitは`HEAD`からインデックスへのステージ済み差分を表示しません。ステージ済み内容の確認には通常のGitツールを使ってください。

## ファイル差分を読む

1. **Unstaged changes**で`j`と`k`を使い、ファイルを選びます。
2. 必要なら`l`で差分ペインへフォーカスを移します。
3. `j`、`k`、`Ctrl-d`、`Ctrl-u`で上下にスクロールします。
4. 長い行は`zh`と`zl`で左右にスクロールします。

テキストパッチには旧・新両方の行番号が付き、ヘッダー、ハンク、追加、削除、コンテキスト、メタデータが色分けされます。ファイル種別を判別できる場合は、組み込みの`syntect`と`two-face`の文法セットでコードもシンタックスハイライトします。追加・削除には控えめな緑・赤の背景を使い、トークンの色は維持します。`j` / `k`で選んだ現在行は行全体を塗らず、ガターの細いマーカーで示すため、コードの色を隠しません。バイナリ変更は生のバイト列ではなく要約を表示します。

ファイル種別を判別できない場合や、512 KiB超、10,000行超、1行4 KiB超の入力では、シンタックスハイライトを行わず通常の差分表示へフォールバックします。その場合も差分種別の色と行移動は利用できます。

画面幅が110列未満では、フォーカス中のペインだけが表示されます。ファイル一覧と差分の移動には`h`と`l`を使います。全キーは[キー操作とレイアウト](/ja/guides/navigation/)を参照してください。

## 外部で編集した後に更新する

エディターや別プロセスがリポジトリを変更したら`r`を押します。更新後も同じパスが存在すれば選択を保ち、キャッシュ済み差分を破棄して古い内容が残らないようにします。

ChronoGit自身が選択ファイルをステージ、復元、編集することはありません。ただし、起動中に別のプロセスがリポジトリを変更することはあります。

## 大きなファイルと特殊なファイル

- テキスト差分が標準出力の8 MiB上限に達すると処理を止め、途中までの内容に切り詰め表示を付けます。
- バイナリ差分はGitの要約として表示します。
- Unix上の非UTF-8パスは内部でバイト列のまま保持し、表示時だけ代替文字を使います。
- 選んだ未追跡ファイルが差分読み込み前に消えた場合、差分ペインに復旧可能なGitエラーを表示します。外部の状態を直して`r`を押してください。
