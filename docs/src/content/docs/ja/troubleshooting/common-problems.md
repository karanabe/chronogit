## `an interactive TTY is required`

`chronogit`をターミナルで直接実行します。パイプ、出力キャプチャ、標準入出力のリダイレクト、切り離したバックグラウンドタスクでは実行しないでください。stdinとstdoutの両方が対話型である必要があります。

例外として、`chronogit --help`と`chronogit --version`はTTYなしで動作します。

## リポジトリを検出できない

再実行する前に引数を確認します。

- パスが存在するディレクトリであること。
- リポジトリルートまたはその下のディレクトリであること。
- Gitがインストールされ、`PATH`から実行できること。
- bareリポジトリではないこと。

OSまたはGitから原因を取得できた場合、起動時の診断に原因チェーンが続きます。実行ファイルがない、権限がないといった最初の具体的な原因を直してください。

## Changesが空、またはファイルが表示されない

Changesは意図的にインデックスからワークツリーへの側だけを表示します。

- ステージ済みだけのファイルは非表示です。
- ステージ済みと未ステージの編集があるファイルは、未ステージ部分だけを表示します。
- クリーンなリポジトリでは`No unstaged changes. Staged-only files are hidden.`と表示します。

ステージ済み内容は`git diff --cached`などのGitインターフェースで確認してください。

## ペインにGitエラーが表示される

選択後にリポジトリが変わった、ファイルが消えた、読み取り権限がない、Gitメタデータが壊れている可能性があります。外部の状態を直し、`r`で現在のビューを再読み込みします。

実行時エラーは可能な限り復旧可能です。他のペインは利用でき、代替としてリポジトリ変更を行うこともありません。

## 差分が切り詰められる、またはコマンドがタイムアウトする

テキスト差分は8 MiB、Gitコマンドは30秒で停止します。メモリ使用量と終了時間を制限するための意図的な境界です。完全な結果が収まらない場合は、Gitでより小さなファイルや狭いrevisionを調べてください。

履歴やツリー項目などの機械可読な結果は、不完全な場合に拒否されます。完全であるかのようには表示しません。

## バイナリファイルにテキストパッチがない

バイナリ変更は要約として表示します。ChronoGitはバイナリ内容を描画せず、外部の変換プログラムも起動しません。

## ターミナルが小さすぎる

80列×24行以上に広げてください。それ未満では通常画面を安定したサイズ警告に置き換えます。`Q`と`Ctrl-C`は安全に終了するため引き続き使えます。

80〜109列では、Changesだけが1つずつ全幅表示になります。`Ctrl-w h`と`Ctrl-w l`でファイル一覧と差分を切り替えます。Historyは全幅の3段をすべて表示します。

## ツリーファイルに変更がないと表示される

ツリーは変更ファイルだけでなく、選択コミットの全項目を表示します。そのため、変更されていないファイルを選ぶと、現在のroot/parent比較では変更がないと表示されます。`\t`で変更ファイル一覧へ戻れます。

## ターミナルが復元されない

通常終了、`Q`、`Ctrl-C`、エラー、panicではターミナル状態を復元します。強制終了（`SIGKILL`）、ターミナルエミュレーター障害、システム中断ではcleanupを実行できません。

ターミナルのリセットコマンドを試します。

```sh title="ターミナル"
reset
```

Unixシェルで入力がまだechoされない場合は`stty sane`を実行します。強制終了なしで問題を再現し、OS、ターミナルアプリ、終了方法、`Q`または`Ctrl-C`を使ったかを添えて報告してください。
